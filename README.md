# hd-server

A custom server for the mobile game *Hay Day*, written in Rust. It targets
**Hay Day 1.43.150 (build 1598)** on Android (x86 and arm64-v8a).

A patched client can complete the bootstrap and encrypted login, load its farm,
and keep playing. The farming commands it sends are replayed into a saved
per-account state. See [progress](docs/progress.md) for what works and what
doesn't yet.

This is a research and preservation project. It is **not affiliated with,
endorsed by or sponsored by Supercell**. Read the [legal notice](LEGAL.md)
before using it.

## Quick start

```sh
cargo build --release
cp config.toml.example config.toml
cargo run --release -- --config config.toml
```

You also need a `resources/` directory generated by
[hd-dumper](https://github.com/eliaswen/hd-dumper), and a client repackaged by
[hd-patcher](https://github.com/eliaswen/hd-patcher) with this server's public
key. The [install guide](docs/install.md) covers each step.

## What this repository contains

- Original Rust code only. There is no game code, APK, asset or data table in
  this repository, and none is embedded in the executable.
- No key material. The server generates its own X25519 key on first start.

## Source layout

| Path | Contents |
| --- | --- |
| `src/main.rs` | CLI and startup |
| `src/config/` | Settings file |
| `src/net/` | HTTP bootstrap, game connections, session state machine, admin listener |
| `src/protocol/` | Byte-stream codec, frame codec, crypto, message catalogue and bodies |
| `src/game/` | Home model, starter farm, progression, command schema, development friends |
| `src/replay/` | Replay of client commands into the saved farm |
| `src/storage/` | Account store |
| `src/data/` | Runtime resource loader |

## AI Usage

This project was, in large part, written by AI, including code, comments and
documentation. I reviewed everything, but since some people are uncomfortable
with AI-written code, I'm pointing it out.

### Details

Models used:

- Claude Opus 5.5: rust code generation, documentation, static and dynamic analysis of the x86 client
- GPT 6.1 Sol: Rust code generation, harder problems
- Deepseek V4.1 Flash 1017: static and dynamic analysis of the x86 client; used when Opus guardrails prevented analysis.
- Claude Sonnet/Haiku 5.5: documentation, comments
- GPT 6 Luna: documentation, comments, limited code generation
- Kimi 3.1 Pro: static and dynamic analysis of the x86 client; used when Deepseek failed.
- GPT 6.1 Terra: Rust code generation

Models are shown in order of usage.
